# 信号与任务状态规则（吸收 wechat-intelligence-hub signal-rules 精华，适配 digger 数据层）

本文件是 `wd followups` / `analyze --mode signals` 输出的解读尺：启发式只负责捞证据，判断用本规则。

## 1. 证据分级

- **已确认**：品牌方/项目方明确邀请，或给出 brief/预算/排期，或用户已人工确认。
- **高概率**：多项强信号相互印证（hints ≥ 2，机器标 high），但尚无直接对接人。
- **待核实**：单一转发、模糊口头信息、身份不明（机器标 medium 的默认档）。
- **仅供存档**：普通讨论、行业信息、泛招聘、线报群优惠信息、羊毛群接龙——不进今日行动。

**不要把机器置信度当事实。** 每个高概率/待核实项都要说明还缺什么证据（对接人？brief？预算数字？）。

## 2. 角色归属

- `品牌/项目方`：给出规则、预算或交付要求的需求方。
- `中间人/Agency`：组织招募、收集名单、转交品牌、负责结算。
- `推荐人`：愿意介绍对接人，但不负责执行。
- `加热者`：只领红包、点赞、接龙、转截图——**不作为建联对象**。
- `身份待核实`：只有转发，无法判断。

线报群/羊毛群的优惠转发（digger 实测最大噪声源，如「银行 x 美团 5 折」）全部属加热者/仅供存档。整群抑制用 `wd followups --feedback chat:<chat_id> --verdict ignore`，单条误报用 `--feedback item:<id> --verdict false_positive`。

## 3. 任务状态语义

- `signal`：单条原始证据，不等于商机。
- `candidate`（digger 默认 new）：信号聚合的待审核候选，**14 天无新证据自动过期**（status=stale）。
- `opportunity`：有人工确认证据（triage pursue/wait/won 或 feedback confirmed）。
- `stale`：过期候选，保留证据不进今日行动；新信号到来自动复活。

- `待回复`（现算，不持久化）：对方提出问题、请求确认或点名我方，且至今没有我方消息跟进。
- `待兑现承诺`（持久化 kind=commit）：我方答应发送初稿/报价/大纲/数据等。**对方回「好的/嗯嗯」只关闭待回复，不关闭承诺。**
- `等待对方`（现算）：我方已完成当前动作（含对方已短应答我方交付），在等预算、brief、审核或结果。
- 礼貌性结束语不是任务；泛泛的「后面有机会联系」只产生低优先级复联，不产生当日待回复。

## 4. Triage 与反馈学习

```
wd followups --list                          # 看开放条目
wd followups --triage 12 --decision pursue --note "已加微信"   # pursue/wait/won 记为确认
wd followups --triage 7 --decision ignore                      # 连带 chat 级抑制
wd followups --feedback chat:xxx@chatroom --verdict false_positive --note "纯线报群"
```

- `confirmed`：升级为正式机会——优先级 ≥5、置信度 confirmed、永不过期。
- `low_priority`：优先级封顶 1，不再升格。
- `false_positive` / `ignore`：该条目（或全会话）后续同类信号不再入状态机。
- `won` / `lost` 后同 key 出现新信号：新开一条候选，不复活旧记录。

## 5. 复联规则

- 两个方向都提醒：对方最后发言后长期未续（球可能在我方）、我方最后发言后长期无回应（确认再推还是归档）。
- 后来的新合作、结算可以覆盖更早的暂停与负面信号——复联前先看该会话最近窗口有无新动作。
- 只有对方明确说「下一批、之后联系」才构成下一批窗口；我方期待和第三方猜测不算。
- 未到跟进日期的放等待区，不挤进立即处理。

## 6. 摘要质量（digest/report 同样适用）

- 严格使用用户给定时间窗口；未给时 `analyze` 默认近 7 天、`followups` 默认 30 天。
- 先按时间+话题分段再归纳，不流水账复述。
- 商单栏目与培训/咨询栏目分开；活动、招聘、羊毛优惠单独标记。
- 高活跃不等于高价值：闲聊、刷屏、接龙只统计，不上重点。
- 建议必须是针对用户的下一步（找谁、问什么、何时跟进），不输出与证据无关的模板话。

## 7. 计数口径（改评分/阈值前必读）

每个指标先声明**怎么算、为什么这么算、在什么语境下失效**，再谈取值。以下口径来自实测踩坑，改动前请读完。

### 7.1 问答密度（`chat_quality`）

- **定义**：含 `？`/`?` 的文本消息数 ÷ 非空文本消息数。
- **语义**：原为「真实对话」反向信号（减分），隐含前提是「广告/机器人不发问句」。
- **失效语境**：电商线报群。其话术是高度互动的问答（「还有吗？」「怎么领？」「要的扣1？」），问号密度与真实讨论群同级。实测某京东优惠群问号密度 31.6%，同时 97.8% 链接、100% 单一发送者广播。
- **修正口径**：仅当**链接密度 < 0.8** 时计入真实对话；链接主导时在 reasons 注明「不计真实对话」，不减分。
- **不要**当全局真理：链接少、问句多、发言分散的群仍是健康讨论群。

### 7.2 口令/链接密度（`chat_quality`）

- **定义**：命中 `LINK_PATTERNS`（http(s)、「复制这条」、淘口令、平台+下单词）的文本数 ÷ 非空文本数。
- **分级**：≥ 0.8 记 +25（近乎纯转发）；≥ 0.4 记 +15。
- **为什么分级**：单一 0.4 阈值让 41% 与 98% 同分，近乎纯转发的群沉在阈值下（实测 97.8% 链接的群仅得 +15）。
- **失效语境**：正常社群分享资料时链接也会上升。故高链接**只在同时满足少数发送者广播**（7.3）时才升格为噪声结论。

### 7.3 广播群判定（`chat_quality`）

- **定义**：活跃发送者 ≤ `BROADCAST_MAX_USERS`(6) 且链接密度 ≥ `LINK_DOMINANT`(0.8) → +20。
- **为什么用发送者数**：线报群是「少数人广播给多数人」，实测驱动者 2-6 人；真实社群为双位数。这是区分广播与分享的关键维度，不能由发言集中度单独替代（集中度在小编号群会失真）。
- **边界**：发言者 ≥ 8 的正常群实测链接密度普遍 < 40%，不误伤。新增群类型时先复核。

### 7.4 群名特征词（`chat_quality`）

- **定义**：群名命中 `NAME_NOISE_WORDS`，每词 +5，上限 +40（首词 25 起）。
- **依赖**：名称必须真实解析。曾因 `contact.db` 以 `mode=ro` 打开失败（WAL 且无 `-shm`），`chat_name` **100% 退化为 `@chatroom` id**，本信号从未生效——名为「某线报群（名称含广告特征词）」的群在名称维度得 0 分。现由 `_connect_ro` 修复（`mode=ro` 失败回退 `immutable=1`）。
- **复核方式**：`wd.py chats` 输出中 `name` 若大量等于 `chat_id`，说明名称解析又断了，先修连接再谈评分。
- **语义**：群名是**证据不是判决**。实测「羊毛线报优惠群」若为 10 人活跃讨论，群名 +35 会被「活跃无支配者」−10 抵消回 25/normal——这是刻意保留的平衡，不要为「更强」取消反向信号。

### 7.5 排除口径（`FOLLOWUP_EXCLUDED_LEVELS`）

- **定义**：`followups` 排除 `noise` 与 `low`；`roundup` 只排除 `noise`。
- **为什么不同**：商机扫描要求精度（low 群实测全是线报/羊毛群，其 "deal" 信号 100% 为电商转发）；`roundup` 成文要求素材广度，刻意保留 low。
- **改动影响**：放宽 followups 排除范围会立刻抬高噪声；收紧 roundup 会丢失素材。

### 7.6 相关性策略（`relevance.json`，可选）

- **定义**：`include` 主题加分、`exclude` 主题直接不入库、`chat_trust` 按会话调分。默认路径 `~/.config/wechat-digger/relevance.json`，缺失即空策略。
- **前提**：**空策略必须是 no-op**——未配置时行为与引入前逐字一致，这是该模块的兼容契约（有测试锁定）。
- **不可覆盖**：人工 `confirmed` 的信号不受 `exclude` 拦截。
- **失效语境**：关键词匹配无消歧能力（「投资」会命中「投资骗局」）。宁可少写几词，不要用它做语义判断。

### 7.7 通用纪律

- 改任何阈值前，先跑三窗口（30/90/365 天）比对分层变化，确认不是过拟合单一窗口。
- 评分类指标必须能给出 `reasons`：说不出理由的分数不可维护。
- 数据依赖型断言要标注依赖的会话与时间范围；数据漂移时应自证失效，而非静默通过。
