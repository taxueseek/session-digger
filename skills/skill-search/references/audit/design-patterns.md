# 设计模式库

构建 skill 时，先选模式再写内容。模式决定 body 的骨架。

--------

## 模式一：顺序工作流

适用：步骤固定、有明确先后顺序的任务。

结构：

```
Phase 1：准备
Phase 2：执行
Phase 3：验收
```

要点：

- 每个 Phase 有明确的输入和输出
- Phase 之间用上一个的输出作为下一个的输入
- 关键节点有检查点

示例：简历诊断（读取 → 逐项诊断 → 输出报告）

--------

## 模式二：路由分发

适用：一个入口，根据条件走不同路径。

结构：

```
判断条件 → 路径 A / 路径 B / 路径 C
```

要点：

- 判断条件必须明确，不能靠「感觉」
- 每条路径独立，不互相依赖
- 兜底路径：条件都不满足时怎么办

示例：工具类 skill 按输入类型分流

--------

## 模式三：迭代精炼

适用：输出需要反复打磨、逐步逼近最优。

结构：

```
生成初稿 → 评审 → 修改 → 再评审 → ... → 达标
```

要点：

- 评审标准必须预先定义
- 设最大迭代次数，防止死循环
- 每轮迭代必须有明确的改进方向

示例：文案优化、代码重构

--------

## 模式四：多工具协调

适用：需要调用多个外部工具或 API。

结构：

```
准备输入 → 调用工具 A → 处理结果 → 调用工具 B → 合并输出
```

要点：

- 每个工具调用有错误处理
- 工具之间传递的数据格式明确
- 有降级方案：工具不可用时怎么办

示例：搜索 + 分析 + 生成报告

--------

## 模式五：领域知识库

适用：需要专业知识支撑的 skill。

结构：

```
知识索引（Level 2）→ 深度参考（Level 3）
```

要点：

- Level 2 只放执行指令和关键判断标准
- Level 3（references/）放详细知识
- 按需读取，不一次性加载所有知识

示例：投资分析、医学诊断

--------

## 模式六：对话访谈

适用：需要从用户获取信息才能执行。

结构：

```
收集信息（2-3 个问题）→ 确认理解 → 执行 → 交付
```

要点：

- 每次最多问 2-3 个问题，不要一次性问 10 个
- 问题要具体，不要开放性
- 信息不完整时给默认选项，不要卡住

示例：需求澄清类 skill 的三问快检

--------

## 选模式的原则

1. **简单优先**：能用顺序工作流就不用迭代精炼
2. **匹配复杂度**：3 步骤的任务不要用 6 步骤的模式
3. **可组合**：复杂 skill 可以组合多个模式（如：路由分发 + 顺序工作流）
