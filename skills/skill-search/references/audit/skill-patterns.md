# Skill 建设优秀模式

从大量 skill 实践中总结的可复用模式。构建或审查 skill 时对照使用。

---

## 模式 A：路由表标准化（解决触发重叠）

**问题**：多个 skill 的触发词重叠，导致同一个请求被多个 skill 抢触发。

**方案**：每个路由层 skill 维护明确的路由表和互斥边界。

```markdown
## 路由表
| 用户说的 | 路由到 |
|---------|--------|
| 「分析股票」「这只怎么样」 | stock-analysis |
| 「基金」「ETF」 | fund-investor |

## 边界
- DO NOT 做分析，只做路由
- 不确定时问一句，不要猜
- 情绪问题不路由到这里 → 通用对话
```

**实践参考**：约 100 行的路由类 skill，路由表最清晰。

---

## 模式 B：渐进式加载（解决 bloat）

**问题**：SKILL.md 超过 300 行后，每次触发都加载大量不需要的内容，浪费 token。

**方案**：三层加载 —— 核心流程始终加载，深度参考按需读取。

```markdown
## 核心流程（始终加载）
1. 识别 → 2. 诊断 → 3. 输出

## 深度参考（按需读取）
| 场景 | 读取文件 |
|------|---------|
| 需要案例库 | references/cases.md |
| 需要完整框架 | references/full-framework.md |
| 需要边界条件 | references/edge-cases.md |
```

**红线**：SKILL.md body 不超过 300 行。超出就拆到 references/。

**实践参考**：294 行的技能采用 5 个按需 reference；103 行的 CLI 封装技能不把脚本内容加载进 context。

## 模式 C：触发词三要素（解决触发不准）

**问题**：触发词太宽导致误触发，太窄导致漏触发。

**方案**：每个 skill 的 description 包含三层触发定义。

```yaml
description: |
  [One-line description of what this skill does]

  Trigger on: [精确触发词1], [精确触发词2], [模糊触发词1]
  Also trigger when user says: "[间接表达方式]"

  DO NOT use when:
  - [相邻场景A] → use [other-skill-A]
  - [相邻场景B] → use [other-skill-B]
```

**三层要素**：
1. **精确触发词**：用户明确说出的关键词（「分析这只股票」）
2. **模糊触发词**：用户间接表达的意图（「这个能不能买」）
3. **排除条件**：明确什么情况下不该触发，该用哪个相邻 skill

**标准**：至少 5 个触发词（覆盖精确/模糊/间接三种表达）+ 至少 2 条排除条件。

## 模式 D：视角卡模板（角色视角类 skill）

**问题**：角色视角类 skill（如「用老板的眼光看」「用投资人的眼光看」）结构不一致，容易混淆。

**方案**：统一的「世界观」模板。

```markdown
## 这个世界的公理（3-5条核心信念）
## 这个世界的语言（关键词和术语表）
## 这个世界的硬规则（判断标准和决策规则）
## 这个世界的盲区（不擅长什么、会忽略什么）
## 标志性问题（会问什么问题）
## 与其他视角的区别（对比表，防止混淆）
```

**实践参考**：角色视角系列 skill 采用统一结构，切换清晰。

---

## 模式 E：CLI 工具封装（复杂操作类 skill）

**问题**：多步骤 API 操作写在 SKILL.md 里，既浪费 token 又容易出错。

**方案**：把复杂操作封装成 CLI 命令，SKILL.md 只负责「什么时候用」和「怎么用」。

```markdown
## 操作命令
| 意图 | 命令 |
|------|------|
| 搜 X | `$SK search <X>` |
| 详情 | `$SK inspect <X>` |
| 导出 | `$SK export <id> --format md` |

## 脚本位置
scripts/cli.py — 包含缓存 + 重试 + 错误处理
```

**实践参考**：103 行的 CLI 封装 skill；CLI 入口 + 多子命令系列。

## 模式选择决策树

```
要建什么类型的 skill？
├── 路由/入口类 → 模式 A（路由表标准化）
├── 内容密集类（>300行） → 模式 B（渐进式加载）
├── 角色视角类 → 模式 D（视角卡模板）
├── API/工具操作类 → 模式 E（CLI 封装）
└── 所有 skill → 模式 C（触发词三要素）必须做
```
