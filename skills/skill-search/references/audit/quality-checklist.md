# Skill 质量 Checklist

构建或审查 skill 时逐条核对。每条标注 PASS / FAIL / WARN。

---

## 零、Token 效率（Level 0）

- [ ] SKILL.md <80 行（不含参考文档索引）
- [ ] 没有"必读"的全量参考文档（改为按需读取）
- [ ] 参考文档间无重复内容
- [ ] 路由表无冗余（不重复指向同一 skill 的不同模式）
- [ ] 真源与注册副本同步
- [ ] 无备份目录残留（*.bak/ 已清理）
- [ ] 版本号一致（SKILL.md + 脚本 + 目录名）
- [ ] 无断链引用（所有 references/* 文件存在）
- [ ] 无硬编码绝对路径

---

## 一、触发机制（Level 1）

- [ ] Description 有一句话说清 skill 做什么
- [ ] 「Use when」包含 5+ 触发词
- [ ] 触发词覆盖精确表达和模糊表达
- [ ] 「Use other skills for」排除了相邻场景
- [ ] 没有和其他 skill 的 description 触发词碰撞
- [ ] Description 当分类器 prompt 写，不是当文档写

## 二、目的与边界

- [ ] 目的一句话写清楚，可以用来做取舍
- [ ] 目的不是太宽泛的描述（「负责XX」不合格）
- [ ] 能力边界明确（不做什么）
- [ ] 权限边界明确（不应该做什么）

## 三、交付标准

- [ ] 交付标准可验收，第三方能判断是否达标
- [ ] 不含「高质量」「专业」等不可验收的词
- [ ] 有具体的输出模板或示例

## 四、指令质量（Level 2）

- [ ] 用对话语言写，不是说明书口吻
- [ ] 先写例子再写规则（或至少有例子）
- [ ] 每条指令做了删除测试（删掉它 Agent 会做错吗？不会就删）
- [ ] Body 控制在 500 行以内
- [ ] 有可执行的代码块或命令（不是纯文本指导）

## 五、结构完整性

- [ ] 有核心工作流（步骤清晰）
- [ ] 有验收协议或质量自检
- [ ] 有迭代触发条件（什么时候该更新）
- [ ] 复杂 skill 有 references/ 目录存放深度参考

## 六、用户体验

- [ ] 「健忘实习生」检验：第一次读能做对吗？
- [ ] 产物 < 150 行（简单 skill 不膨胀）
- [ ] 没有替用户假设触发词
